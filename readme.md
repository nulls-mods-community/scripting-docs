# NB Scripting

#### Канал в ТГ: [@danyanull](https://t.me/danyanull)

NB Scripting — это технология, позволяющая создавать и использовать пользовательские скрипты в боях Null’s Brawl.

## Как это работает?

При запуске каждого боя сервер проверяет заданы ли для него пользовательские скрипты. Если да — они загружаются.

Загруженные скрипты имеют доступ только к своему бою. Подробнее о том, как мы изолируем скрипты, смотрите в разделе [Безопасность](#безопасность).

Каждый скрипт должен иметь глобальную функцию `tick()`, которая будет вызываться каждый игровой тик.

Скриптам также предоставлена возможность подписываться на различные события, например, при получении урона конкретным персонажем.

При завершении боя скрипты уничтожаются.

## Язык программирования

Скрипты пишутся на языке Lua. В качестве основного интерпретатора на данный момент используется [Luau](https://luau.org).

Поведение Luau в некоторых аспектах может отличаться от того, что ожидается стандартами Lua. Подробнее об этом читайте здесь: https://luau.org/compatibility/.

## Доступное API

Важно заметить: наш сервер боев написан на языке Java. Поэтому наше API строится поверх работы с Java-объектами.

Каждый из этих объектов в рамках Lua представлен как *userdata*, а не *table*. Вы не можете создавать такие объекты самостоятельно — только получать их при
помощи нашего API.

Полный список классов есть в отдельном документе: [API Reference](reference.md).

У каждого скрипта есть доступ к объекту класса [Server](reference.md#server). Этот объект существует в единственном экземпляре и является основной точкой входа
в наше API. Он доступен посредством глобальной переменной **server**.

### Основные действия с Java-объектами

Вы можете получать и выставлять поля также, как с обычной Lua-таблицей:

```lua
clientInfo.ultiCharge = math.min(server.tick, clientInfo.maxUltiCharge)
```

Имейте в виду, что если поле помечено как readonly, то попытка его изменить не выбросит ошибку. Но и значение изменено не будет.

Вы можете вызывать доступные методы с помощью оператора двоеточия:

```lua
clientInfo = server:getClientInfo(0)
```

Для объектов класса Iterable и наследников (List, ArrayList) можно использовать цикл for:

```lua
for i, character in server.objectManager:getCharacters() do
    ...
end
```

### Вспомогательные функции

Наше API предоставляет несколько вспомогательных функций. Они не работают с Java-кодом сервера напрямую, но помогают вам создавать или получать доступ к
некоторым объектам.

| Название       | Тип                                     | Применение                                                                                                          |
|----------------|-----------------------------------------|---------------------------------------------------------------------------------------------------------------------|
| lookup         | (type: number, name: string) ⇒ Data     | Позволяет получить объект Data по его типу и названию.                                                              |
| createObject   | (data: Data) ⇒ LogicGameObject          | Позволяет создать новый экземпляр LogicGameObject для конкретного Data.                                             |
| createCallback | (class: string, arg: function) ⇒ Object | Позволяет преобразовать Lua-функцию в Java-объект. Используется для подписки на события.                            |
| enumAsTable    | (class: string) ⇒ table                 | Позволяет получить Lua-таблицу, которая представляет конкретный Java Enum. Ключ — название, значение — Java-объект. |
| log            | (params: string...) ⇒ void              | Печатает сообщение в отладочные журналы и в чат дружеской комнаты, если применимо.                                  |

Эти функции доступны глобально.

### Наследование и полиморфизм

Некоторые классы в Java могут быть абстрактными. Такие классы не могут иметь экземпляров. Они используются, чтобы обобщить несколько классов-наследников в один
тип с общими полями или методами.

Например, [LogicGameObject](reference.md#logicgameobject) — это абстрактный класс. Когда вы вызываете `createObject()` или `objectManager:getObject()`,
фактически вы получите экземпляр одного из классов наследников: [LogicCharacter](reference.md#logiccharacter), [LogicItem](reference.md#logicitem),
[LogicProjectile](reference.md#logicprojectile) или [LogicAreaEffect](reference.md#logicareaeffect).

Это работает в обе стороны: `objectManager:addObject()` в качестве аргумента тоже может принять любой из этих классов-наследников.

Более того, это работает не только с абстрактными классами. В Java всегда можно передать или вернуть объект дочернего класса, даже если ожидается объект
родительского класса. Правда примеров таких классов в доступном API сейчас нет.

Дополнительно стоит рассмотреть Iterable, List и ArrayList. ArrayList является наследником абстрактного класса List, а он в свою очередь наследует абстрактный
класс Iterable. В рамках доступного API другие наследники List или Iterable не используются — а значит, если вы видите Iterable или List, то это всегда
ArrayList.

### Подписка на события

Рассмотрим [LogicCharacter](reference.md#logiccharacter) и его поле **takingDamageListeners**. Это список подписок на событие получения урона.

Этот список представлен классом ArrayList. То есть это Java-объект, который внутри себя хранит другие Java-объекты. Мы не можем взять и добавить в него
произвольную Lua-функцию напрямую.

Поэтому и существует `createCallback()`. Его использование выглядит так:

```lua
local callback = function(target, projectile, damage, someData, origin)
    ...
end

local callbackImpl = createCallback("DamageEventListener", callback)
character.takingDamageListeners:add(callbackImpl)
```

С помощью этой функции мы преобразовали Lua-функцию в Java-объект класса DamageEventListener, который уже пригоден для добавления в список. Потрясающе!

Обратите внимание: если вызвать `createCallback()` дважды с одной функцией, вы получите два разных объекта. Имейте это в виду, если захотите проверить подписку
на событие с помощью `takingDamageListeners:indexOf()`.

На данный момент поддерживаются следующие классы:

| Название            | Тип                                                                                                                               | Применение                             |
|---------------------|-----------------------------------------------------------------------------------------------------------------------------------|----------------------------------------|
| DamageEventListener | (source: LogicCharacter,<br/>projectile: LogicProjectile, <br/>damage: number,<br/> data: Data,<br/> origin: AttackOrigin) ⇒ void | События получения или нанесения урона. |

## Безопасность

Каждый отдельный скрипт выполняется в своей изолированной песочнице. Доступа к системным API нет. Вы можете работать только с теми объектами, которое вам
предоставляет API NB Scripting, а также с некоторыми безопасными функциями стандартной библиотеки.

Каждый скрипт имеет квоту по памяти и CPU Time. Скрипт может быть выгружен в любой момент, если квота будет превышена.

| Ресурс   | Базовая квота                                                     |
|----------|-------------------------------------------------------------------|
| CPU Time | Не более 15 миллисекунд реального времени за один вызов Lua-кода. |
| Память   | Не более 16 MiB на весь скрипт. Java-объекты не учитываются.      |
